# SEO/meta strengthening and focused GitHub research

Scope: implement the owner's approved metadata improvements while keeping the current Vercel test origin. No domain purchase/migration, deployment, Search Console access, signing or changes to immutable published content. Preserve pending opening-performance and icon work in this checkout.

Implementation decisions:

- Keep index policy separate from robots display directives; allow large image previews on indexable pages without disabling OG/JSON-LD. Restrict dynamic activity snippets using data-nosnippet.
- Build one typed WebSite/Person/ProfilePage graph using real handles and the existing visible portrait; article author references the same Person ID. No invented credentials/statistics.
- Carry valid revision numbers through preview resolution, social image cache/URLs and historical oEmbed. Canonical policy remains pathname-based. Use a stable social motto independent of the functional visible-motto cookie.
- Allow indexing of public eligible social images, retain noindex for unlisted/private content. Preserve actual cover imagery as the Article.image source; do not label a text/logo card as a representative article photo or fabricate a cover.
- Verify production HTML with an explicit synthetic public origin, including duplicate metadata, graph IDs, historical image URL and robots policy. Existing local tests deliberately omit a public origin, so their indexability checks alone are insufficient.

Focused GitHub research budget: at most three repositories, at most two targeted file reads each. schema-dts offers compile-time graph validation with no browser runtime and is a direct fit. Unhead's canonical/name/property deduplication design informs rendered-head regression checks; no need to replace an already centralized Astro layout with a client head manager. SEOntology is a research vocabulary/OWL workflow project rather than a built-HTML validator; not an application dependency for this small portfolio. Decisions and verification results follow below.

## GitHub findings

- [google/schema-dts](https://github.com/google/schema-dts/blob/main/README.md): adopted exact dev dependency 2.1.0 and type-only imports for the shared graph. This checks vocabulary shape during TypeScript validation without adding browser JavaScript; it does not prove Google's rich-result eligibility.
- [Unhead deduplication](https://github.com/unjs/unhead/blob/main/packages/unhead/src/utils/dedupe.ts): borrowed singleton canonical/meta identity checks for production-rendered HTML. Existing Astro Layout already owns the head, so installing a runtime manager would duplicate responsibility.
- [SEOntology](https://github.com/seontology/seontology): evaluated and declined; its OWL/RDF workflow vocabulary is a poor fit for validating this small site's rendered HTML.

The independent source review found a historical Discord card's Open page button still targeting the latest revision. The button now retains the selected revision, with a production-head regression assertion. No other actionable SEO findings were reported.

Article cover imagery remains an editorial gap: current listed articles have no authored cover. Their text/logo share cards are not presented as representative article imagery. No search-ranking or rich-result guarantee is implied.
